# Архитектура AutoService AI 1.0

Настольная программа для Windows: Python 3.12 + PySide6 (Qt 6), локальная SQLite, без серверов и облачных сервисов.

## Слои

```
src/autoservice/
  domain/        бизнес-правила без базы: деньги, наценка, FIFO, статусы, нормализация артикулов
  persistence/   модели SQLAlchemy, типы столбцов (копейки/тысячные), подключение, миграции Alembic
  application/   сценарии операций (каждая операция — одна транзакция): склад, закупки, продажи,
                 ремонты, оплаты, расходы, отчёты, главная панель, настройки, авторизация, журнал
  documents/     PDF (ReportLab), Excel/CSV (openpyxl), печать (QtPdf + QPrinter), интерфейс ККТ
  knowledge/     библиотека автодела: хранение документов, извлечение текста, поиск FTS5, правила диагностики
  ai/            помощник (режим A), адаптер локальной модели (режим B), OCR, разбор накладных, рекомендации
  backup/        копии (SQLite backup API → zip → [AES-GCM]), проверка, восстановление, расписание, DPAPI
  security/      пароли (scrypt), права ролей, безопасные пути и фильтр импортируемых файлов
  ui/            интерфейс PySide6: главное окно, 12 разделов, диалоги
  app.py         точка входа; selftest.py — самопроверка установленной программы
```

Правило зависимостей: `ui → application/ai/documents/knowledge/backup → domain/persistence`. Интерфейс не обращается
к базе напрямую и не содержит расчётов; финансовые формулы — только в `domain`.

## Данные

| Что | Где |
|---|---|
| Программа | `C:\Program Files\AutoService AI` (заменяется при обновлении) |
| Данные | `C:\ProgramData\AutoServiceAI` (не удаляются при обновлении и удалении программы) |
| База | `...\data\autoservice.db` (SQLite, WAL, `synchronous=FULL`, внешние ключи включены) |
| Вложения | `...\attachments\` (оригиналы накладных, документы библиотеки, фото) |
| Копии | `...\backups\local`, `...\backups\before-update`, внешняя папка из настроек |
| Сформированные PDF | `...\exports\documents\` |
| Журнал программы | `...\logs\autoservice.log` |

Путь к данным установщик записывает в `autoservice.ini` рядом с программой. Для тестов — переменная `AUTOSERVICE_DATA_DIR`.

## Схема базы (основные таблицы)

`users, audit_log, settings, sequences, backup_history, customers, employees, vehicles, vehicle_plate_history,
suppliers, part_categories, parts, part_numbers, part_analogs, part_compatibility, part_suppliers, price_history,
documents, purchase_orders, purchase_items, stock_batches, stock_movements, stock_reservations, stock_adjustments,
inventory_counts, inventory_count_items, supplier_returns, supplier_return_items, sales, sale_items, sale_returns,
sale_return_items, work_orders, work_order_services, work_order_parts, payments, expenses, knowledge_sources,
knowledge_fts (FTS5), diagnostic_rules, ai_recommendations, invoice_imports`.

Ограничения в базе: внешние ключи, `CHECK` на статусы, неотрицательные остатки партий, количество > 0, скидка ≤ суммы,
наценка 0–100 %, уникальность номеров документов и VIN.

## Целостность операций

* Каждая операция — `with ctx.db.transaction()`: документ, складские движения, себестоимость, оплата и запись в журнал
  фиксируются вместе или не фиксируются вовсе.
* Защита от повторного проведения: `UPDATE ... SET status='posted' WHERE id=? AND status='draft'` с проверкой числа строк.
* Проведённое не удаляется: отмена — смена статуса с причиной, временем и пользователем + обратные складские движения
  со ссылкой на исходное (`reversal_of_id`). Черновики, не влиявшие на учёт, удалять можно.
* Дубли закупок: номер документа поставщика + поставщик; дубли файлов накладных — по SHA-256.

## Миграции

Alembic, сценарии в `persistence/migrations/versions`. При запуске (`persistence/migrate.py`):
новая база → создание до последней версии; существующая → копия через SQLite backup API → обновление → при ошибке файл
базы возвращается из копии, программа сообщает об ошибке. База более новой версии, чем программа, не открывается.
Установщик дополнительно копирует базу перед обновлением программы.

## Безопасность

* Вход по паролю; пароли — scrypt с солью; блокировка на 5 минут после 5 неудачных попыток.
* Роли «Администратор» и «Менеджер»; права проверяются в сервисном слое (`security/permissions.py`).
* Журнал действий: входы, проведение и отмена документов, платежи, изменение настроек, копии и восстановление.
* Импорт: только разрешённые форматы, без исполнения кода; DOCX/XLSX читаются как данные; распаковка архивов копий
  проверяет пути.
* Нет сетевых соединений: единственный сетевой код — адаптер локальной модели, ограниченный адресами 127.0.0.1/localhost,
  без системного прокси. Тест `test_31_works_without_network` блокирует сокеты и проводит все основные операции.
* Резервные копии можно шифровать (AES-256-GCM, ключ из пароля через scrypt); пароль для копий по расписанию хранится
  защищённым Windows DPAPI.

## Известные ограничения версии 1.0

* Фискализация (ККТ) не реализована — только нефискальные документы; интерфейс интеграции — `documents/fiscal.py`.
* OCR сканов требует установленного Tesseract OCR (не входит в установщик по умолчанию). PDF с текстом и Excel
  распознаются без OCR.
* Режим B (локальная языковая модель) требует отдельно установленного сервера модели.
* Многопользовательская работа по сети не поддерживается — один компьютер.
* Учёт управленческий: не заменяет бухгалтерскую и налоговую отчётность.
